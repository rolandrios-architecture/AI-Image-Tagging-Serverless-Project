Notes and gotchas:

- Do not paste IAM policy JSON into the S3 CORS editor — that was the earlier mistake. CORS editor only accepts the CORS array JSON.
- If your S3 bucket is behind CloudFront or a different proxy, ensure the proxy forwards OPTIONS and CORS headers unchanged.
- Wait a few seconds after applying CORS before retrying; S3 CORS changes propagate quickly but may take a moment.
- Prefer attaching `s3:PutBucketCORS` only to an admin or CI user that manages buckets; attach object-level permissions (`s3:PutObject`) to your backend role (Lambda, ECS task, etc.) that generates presigned URLs.
